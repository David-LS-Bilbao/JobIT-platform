# Skill neutral: Documentation

## Objetivo

Crear o actualizar documentacion clara, consistente y alineada con el alcance aprobado.

## Cuando usarla

- Al crear README, specs, briefs, checklists o guias.
- Al refinar documentacion antes de PR.
- Al registrar decisiones de producto o proceso.

## Entradas necesarias

- Objetivo de la tarea.
- Rama de trabajo.
- Archivos permitidos.
- Contexto del sprint o spec.
- Criterios de aceptacion.

## Archivos permitidos

Los indicados por la tarea. Si no se indican, pedir aclaracion o limitarse a documentos existentes relacionados.

## Restricciones

- No crear codigo.
- No crear configuracion ejecutable.
- No ampliar alcance sin aprobacion.
- Mantener el contenido en espanol.

## Checklist

- [ ] Rama y estado revisados.
- [ ] Documentos base leidos.
- [ ] Cambios limitados al alcance.
- [ ] Tono profesional y practico.
- [ ] Verificaciones ejecutadas.

## Formato esperado de salida

1. Rama activa.
2. Archivos modificados.
3. Resumen de cambios.
4. Confirmacion de restricciones.
5. Verificaciones ejecutadas.
6. Riesgos o dudas.
7. Siguiente paso recomendado.
